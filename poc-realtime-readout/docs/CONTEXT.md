# 왜 이 화면인가

## 한 줄

배라의 "반응 확인 1개월"은 데이터를 못 모아서가 아니라 **판매와 반응을 한 화면에서 같이 보지 못하는 구조** 때문일 가능성이 크다(파트 1).
그래서 새 수집 도구가 아니라, 이미 있는 데이터를 같은 날짜 축에 올려 매주 결정으로 잇는 화면을 만든다.

## 파트별 연결

| 파트 | 찾은 것 | 이 화면에서 |
|---|---|---|
| 3 현황 | 적자의 주원인은 원가율·지급수수료. 마케팅이 직접 조정할 수 있는 가장 큰 비용은 판촉비(649억, 3년간 2.6배). 판촉을 늘렸지만 점당 매출은 하락. 출시일과 배라데이가 겹쳐 무엇이 먹혔는지 숫자가 섞임 | 판촉 패널: 행사별 증분과 ROI, 출시 첫 주 판매를 맛 수요와 할인 효과로 분해 |
| 3 현황 | 점주 분담 판촉은 70% 사전 동의 필요(2024 동의 조작으로 과징금) | 행사 판정 근거를 숫자로 남겨 점주 설득 자료로 쓸 수 있음 (확장) |
| 1 수집 | 반응은 무료 API로 매일 수집 가능. 판매·광고·채널 지표가 따로 논다. 공개 성과 지표는 '첫 주 목표 대비', '출시 전 대비 일평균', '잠식 여부' | 같은 날짜 축 차트, 목표 대비 맛 수요, 원조 맛 잠식 신호 |
| 1 수집 | 숏폼을 본 10~20대는 바로 사지 않고 며칠 뒤 산다 | '반응에서 판매까지 걸린 날' 패널 (유형별 시차) |
| 1 수집 | 매장 급등 설명 변수: 카카오 로컬(경쟁점), 서울 생활인구 | 매장 표의 '왜' 열 |
| 1 수집 | 섹타나인이 이미 구매 데이터·AI 신제품 도구를 갖고 있음 | 경쟁 도구가 아니라 **섹타나인 데이터 위에 얹는 화면** → 데이터 계약(`schema.py`)을 먼저 고정 |

## 시연 흐름 (11/18)

1. **출시 전(2/28)**: 티저 이틀 만에 검색지수가 평소의 10배 넘게 뜀 → 초도 물량 검토. 지금 방식은 이 신호를 못 봄.
2. **1주차(3/9)**: 맛 수요가 목표의 1.3배대 → 증산 검토. 배라데이 ROI는 1.1대지만 기준선 근거가 5일뿐이라 '잠정'.
3. **2주차(3/16)**: 역세권 매장 하나가 주변 언급은 두 배인데 순위가 200 넘게 떨어짐 → 품절 점검 우선.
4. **3주차(3/23)**: 배라위크 ROI 0.8대 → 중단 검토. 신규 입주 단지 앞 주거 매장 급등, 이유가 같이 뜸.
5. **월말(4/1)**: 월 판매 1위·긍정률 70% 이상 → 재출시 후보. 31데이는 ROI 1.5 → 지속.
6. 마지막 패널: 본사 CSV를 같은 열로 넣으면 그대로 동작.

(숫자는 목 데이터 기준이며 `make data`를 다시 돌려도 같은 값이 나온다. 시드 고정.)

## 본사에 확인할 것 (파트 1에서 이어받음)

- 이달의 맛 반응을 지금 어떤 데이터로, 누가, 어떤 주기로 보는가. 1개월 걸리는 구간은 집계·마감·보고 중 어디인가
- 점주 앱 '플레이버 관리'·매출관리 데이터를 본사에서 매장 × 맛 × 일 단위로 볼 수 있는가
- 매장 '전국 순위'는 무엇으로 매기는가 (매출, 성장률, 객수). 급등 매장을 지금 어떻게 찾는가
- 대행사가 보고하는 광고 지표(CTR, 조회율)와 판매 지표를 한 리포트로 합쳐 보는가
- 행사별 할인 비용과 점주·본사·제휴사 분담 비율 (지금은 할인 환산율 가정)
- PoC용으로 공식 계정 읽기 권한(인스타 인사이트, 유튜브 분석, 네이버 검색광고)을 받을 수 있는가
